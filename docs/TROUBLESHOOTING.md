# Решение проблем

## StreamElements не сохраняет Overlay: 413 Request Entity Too Large

В старых версиях анимации встраивались в JavaScript как Base64. StreamElements сохраняет весь Overlay, поэтому большой виджет мог превышать размер допустимого запроса. Начиная с 0.19.0 файлы персонажей выбираются из медиатеки, а в код входят только их метаданные и ссылки.

1. Открой свой проект в актуальном `preview.html`.
2. Полностью замени HTML/CSS/JS/FIELDS в существующем виджете. Особенно важно заменить старый JS, а не дописать новый код в конец.
3. В «Динозаврики — медиатека» выбери файлы для эфира и сохрани Overlay.
4. Если в Overlay остались другие старые копии виджета со встроенными медиа, обнови и их либо удали ненужные копии.

В CSS копируется один выбранный шрифт. Текст лицензий не включается в копируемый код; он остаётся в отдельном файле архива. Минификация или перенос тех же больших данных из JS в HTML проблему общего размера не решает.

## В превью динозавр есть, в StreamElements его нет

Локальный импорт не загружает файлы в аккаунт. После вставки четырёх вкладок открой настройки Custom Widget → «Динозаврики — медиатека». Для каждого персонажа выбери файл через Upload → Select/Submit и сохрани Overlay. Используй тот же исходник, что в превью.

Если группы нет, проверь, что FIELDS скопирован из превью после загрузки набора. При пустом наборе группа персонажей не создаётся. Проверь формат файла и его воспроизведение в медиатеке, затем в целевом OBS. WebM/MP4 может отличаться поддержкой кодеков и прозрачности; контейнер сам по себе этого не гарантирует.

## Персонаж маленький или размытый

Все персонажи помещаются в общий квадрат с сохранением пропорций. Большие прозрачные поля исходника уменьшают видимую фигуру; обрежь их заранее, затем используй одинаковый файл в превью и медиатеке. Размер персонажа и общий масштаб — разные настройки.

Перевод маленького GIF в WebM не восстанавливает детали. Используй качественный исходник достаточного разрешения. Виджет не пережимает загружаемые анимации.

## Команда не меняет персонажа

Проверь поле «Команда» у нужного файла. Название должно быть уникальным и допустимым. После переименования старое название не остаётся алиасом. В Twitch отправь новую команду с `!`, затем обычное сообщение: изменение видно в последующих сообщениях автора. Убедись, что файл выбран в медиатеке и пользователь не находится в списке игнорирования.

В превью команды меняют также уже показанные сообщения, чтобы удобнее сравнивать персонажей. Это поведение тестового режима.

## Бот не пишет список динозавров

Виджет не отправляет сообщения от имени бота. Создай Custom command StreamElements с ответом из списка под галереей превью. Можно использовать `!interless_chat` и алиасы `!dino`/`!ichat`, если они свободны. Если список большой, раздели его на несколько команд. После переименования обнови ответ бота отдельно.

## Настройки после копирования отличаются от превью

Скопируй все четыре вкладки после последнего изменения. Для оформления действует снимок из превью; отдельно вставлять JSON пресета не нужно. Масштаб и команды, изменённые в StreamElements, имеют собственные сохранённые значения. Проверь их в панели виджета: они не возвращаются автоматически в локальный проект.

Фон страницы, тестовые сообщения и режим продлённого просмотра относятся только к превью. При обновлении того же Custom Widget DATA не очищай: иначе придётся заново выбрать медиа и значения полей.

## Кнопка копирования не даёт доступ к буферу

Используй появившееся выделенное поле с кодом: Ctrl+C → нужная вкладка StreamElements → Ctrl+A → Ctrl+V. Доступ к буферу зависит от браузера и режима открытия локальной страницы; скачивание отдельных файлов для копирования не требуется.

## Чат обрезается

Проверь ширину и высоту области Custom Widget и разрешение источника браузера OBS. Они ограничивают видимую сцену. Старые сообщения при переполнении по высоте могут уходить за верхнюю границу. Для увеличенного масштаба оставь достаточную область, уменьши число сообщений или их ширину/размер. Чередование относится к порядку плашки и персонажа внутри сообщения, а не к размещению по противоположным краям экрана.

Если проблема остаётся, создай [issue](https://github.com/Interless/interless-twitch-chat/issues/new/choose) с версией, шагами и обезличенным примером. HAR и JSON проекта могут содержать данные аккаунта или исходные медиа; для воспроизведения достаточно минимального примера.
