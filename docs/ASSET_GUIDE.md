# Asset Guide

## Набор для каждой роли

Для `broadcaster`, `moderator`, `vip`, `subscriber` и `viewer` подготовьте отдельно:

1. `character` — персонаж рядом с облачком;
2. `decoration` — кость, череп или другой небольшой декоративный элемент.

Тело облачка и текст не должны быть растровыми ассетами: они масштабируются CSS и меняют размер в зависимости от сообщения.

## Именование

Используйте lowercase kebab-case:

```text
broadcaster-character-v1.webp
broadcaster-decoration-v1.svg
moderator-character-v1.webp
viewer-decoration-v1.png
```

Версия в имени позволяет откатить ассет независимо от кода.

## Форматы

| Формат                  | Когда использовать                    | Рекомендация                                |
| ----------------------- | ------------------------------------- | ------------------------------------------- |
| SVG                     | простая векторная графика             | предпочтительно для костей, хвоста и декора |
| WebP                    | сложная растровая иллюстрация         | предпочтительно для персонажа               |
| PNG                     | когда экспорт WebP ухудшает качество  | допустимый fallback                         |
| GIF/APNG/WebP animation | только обоснованная короткая анимация | согласовать из-за CPU и веса                |

SVG не должен содержать scripts, внешние ссылки, embedded HTML или удалённые fonts.

## Размеры и вес

- character source: `512 × 512 px`, рабочая область примерно `400 × 400 px`;
- decoration source: `256 × 256 px`;
- прозрачный фон;
- character: желательно до `300 KB`, максимум `700 KB`;
- decoration: желательно до `100 KB`, максимум `250 KB`;
- animated asset: желательно до `1 MB`, максимум обсуждается отдельно.

Исходник 2× покрывает Retina/HiDPI. Не экспортируйте 4K-картинку для элемента, который отображается около 74 CSS pixels.

## Точка привязки

Персонаж располагается слева от пузыря и выравнивается по нижнему краю. Внутри прозрачного canvas:

- визуальный низ персонажа должен быть около `90–95%` высоты;
- центр массы — около `50%` ширины;
- не помещайте критичные детали в крайние `5%` canvas;
- decoration должна оставаться отдельным файлом и не влиять на silhouette персонажа.

CSS может масштабировать элемент, но не должен исправлять неправильные внутренние поля ассета. У всех ролей используйте одинаковый canvas и сходную визуальную массу.

## Что оставлять отдельным

- character;
- decoration;
- bubble tail, если дизайнер заменяет CSS-вариант;
- дополнительные foreground/background effects;
- анимированные элементы.

Не объединяйте персонажа, облачко и декор в один bitmap: это ломает auto-size и collision measurement.

## Текст

Не встраивайте имя, сообщение, role label или декоративные надписи в изображение. Текст должен:

- изменяться в реальном времени;
- переноситься;
- поддерживать Unicode/RTL;
- масштабироваться настройками;
- оставаться доступным и безопасным.

## Замена в StreamElements

1. Откройте Overlay и выберите Custom Widget.
2. В панели настроек раскройте группу нужной роли.
3. В `Character image` выберите character asset.
4. В `Decoration image` выберите decoration asset.
5. Сохраните Overlay и обновите Browser Source в OBS.
6. Пройдите сценарии роли из `QA_CHECKLIST.md`.

URL из `image-input` приходит через `fieldData`, проверяется `ConfigNormalizer` и передаётся в компонент через `RoleTheme.assets`; менять JSX для нового ассета не требуется.
